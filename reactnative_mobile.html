🚀 ขั้นตอนที่ 1: App เริ่มทำงาน (Boot Flow)

เมื่อผู้ใช้เปิด App ระบบจะทำงานตามลำดับนี้:

1 index.js — จุดเริ่มต้น
ลงทะเบียน App component กับ React Native runtime
import App from './App';
AppRegistry.registerComponent(appName, () => App);
↓
2 App.tsx — เตรียมระบบ
- เรียก DatabaseService.getInstance().initialize() เพื่อเปิดฐานข้อมูล
- แสดง Loading (ActivityIndicator) ระหว่างรอ
- เมื่อพร้อม → แสดง Navigation + หน้าจอหลัก
↓
3 DatabaseService.ts — สร้างฐานข้อมูล
- เปิดไฟล์ฐานข้อมูล SQLite ชื่อ wms.db
- สร้างตาราง 3 ตาราง (ถ้ายังไม่มี): products stock logs
- เปิด Foreign Keys เพื่อรักษาความสัมพันธ์ข้อมูล
↓
4 AppNavigator.tsx — แสดง Tab Bar
สร้าง Bottom Tab Navigation 6 แท็บ: ภาพรวม | สินค้า | โซน | รับเข้า | โอนย้าย | เบิกจ่าย

🗄️ ขั้นตอนที่ 2: ฐานข้อมูล (Database)

ใช้ op-sqlite — SQLite database ที่ทำงานบนมือถือโดยตรง ไม่ต้องต่อ internet

ตาราง 3 ตารางหลัก:

ตารางหน้าที่ตัวอย่างข้อมูล
productsเก็บข้อมูลสินค้าid=1, name="สายไฟ 2.5mm", unit="ชิ้น"
stockเก็บจำนวนสินค้าในแต่ละโซนproductId=1, zone="A1", quantity=25
logsบันทึกประวัติทุกรายการtype="inbound", quantity=10, toZone="A1"

Pattern: Singleton

// เรียกใช้ Database ได้จากทุกที่ผ่าน getInstance()
const db = DatabaseService.getInstance();
const products = await db.getAllProducts();

📱 ขั้นตอนที่ 3: หน้าจอแต่ละหน้าทำอะไร

📊 DashboardScreen — ภาพรวมคลัง
ทำอะไร: แสดงสรุปจำนวนสต็อกทั้งหมด แยกตาม Zone A/B/C + เตือนสินค้าต่ำกว่า Reorder Point
ข้อมูลจาก: getDashboardSummary() + getLowStockProducts()
อัพเดท: ทุกครั้งที่เปิดหน้านี้ (useFocusEffect) + Pull to Refresh
📦 ProductScreen — จัดการสินค้า
ทำอะไร: เพิ่ม / แก้ไข / ลบ สินค้า
ฟอร์มเพิ่ม: อยู่ด้านบน กรอกชื่อ + เลือกหมวดหมู่ → กดเพิ่ม
แก้ไข: กดไอคอนดินสอ → เปิด Modal แก้ไข
Highlight: สินค้าที่ stock ≤ reorderPoint → แสดงพื้นหลังสีส้ม ⚠️
🏭 ZoneScreen — ผังคลังสินค้า
ทำอะไร: แสดงโครงสร้างโซน 3 โซนหลัก (A, B, C) แต่ละโซนมี 3 โซนย่อย
UI: Expandable list — คลิกเพื่อดูโซนย่อยและจำนวนสต็อก
📥 InboundScreen — รับสินค้าเข้าคลัง
ทำอะไร: เลือกสินค้า → เลือกโซน → กรอกจำนวน → รับเข้า
Logic: เพิ่ม quantity ในตาราง stock + บันทึก log ประเภท "inbound"
Validation: ต้องเลือกสินค้า, จำนวนต้อง > 0
🔄 TransferScreen — ย้ายสินค้าระหว่างโซน
ทำอะไร: เลือกโซนต้นทาง → เลือกสินค้า → เลือกโซนปลายทาง → กรอกจำนวน → ย้าย
Logic: ลด stock โซนต้นทาง + เพิ่ม stock โซนปลายทาง + บันทึก log ประเภท "transfer"
Validation: โซนต้นทาง ≠ ปลายทาง, จำนวน ≤ stock ที่มี
📤 OutboundScreen — จ่ายสินค้าออก
ทำอะไร: เลือกโซน → เลือกสินค้า → กรอกจำนวน → จ่ายออก
Logic: ลด stock ในโซนที่เลือก + บันทึก log ประเภท "outbound"
เพิ่มเติม: แสดงตารางประวัติจ่ายออกล่าสุด 10 รายการ

🔄 ขั้นตอนที่ 4: การไหลของข้อมูล (Data Flow)

ตัวอย่าง: ผู้ใช้รับสินค้า "สายไฟ" 10 ชิ้น เข้าโซน A1

1 ผู้ใช้กรอกข้อมูลใน InboundScreen
เลือก: สายไฟ | โซน: A1 | จำนวน: 10 → กด "รับสินค้าเข้าคลัง"
↓
2 Validation ตรวจสอบข้อมูล
เช็ค: สินค้าถูกเลือก ✓ | จำนวน > 0 ✓ → ผ่าน
↓
3 DatabaseService.inbound() ทำงาน
ทำใน Transaction (ทำทั้งหมดหรือไม่ทำเลย):
- INSERT/UPDATE ตาราง stock → A1 เพิ่ม 10
- INSERT ตาราง logs → บันทึกประวัติ
↓
4 แจ้งผลและอัพเดทหน้าจอ
แสดง Toast "รับ สายไฟ 10 ชิ้น เข้า A1 สำเร็จ" → โหลดข้อมูลใหม่

🏭 ขั้นตอนที่ 6: Build APK และ Deploy

1 Push code ขึ้น GitHub (branch: main)
Git add → commit → push
↓
2 GitHub Actions ทำงานอัตโนมัติ
ไฟล์: .github/workflows/build-apk.yml
- Setup Node.js + Java 17 + Android SDK
- npm install (ติดตั้ง dependencies)
- Gradle assembleRelease (build APK)
↓
3 Download APK จาก Artifacts
ไปที่ GitHub → Actions → คลิก build สำเร็จ → Download APK
↓
4 ติดตั้งบนมือถือ หรือทดสอบบน Emulator
ส่งไฟล์ APK ไปมือถือ → ติดตั้ง → ใช้งานได้เลย (ไม่ต้องต่อ internet)
